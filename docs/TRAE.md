日期：2026-10-19。状态：0.1.19 已接入 Windows TRAE CN；真实 Token、独立官方积分登录、手动刷新及重启恢复已验证。Mac 0.1.22 分支已实现本地连接与独立官方积分窗口；安装态真实积分及重启恢复已验证，真实 Token 仍待有记录时验收。

Mac 接入沿用相同的只读数据库采集和余额字段规则。macOS 14+ 使用固定的独立 WKWebsiteDataStore，不与应用主窗口或 WorkBuddy 共用网页登录数据；更早的 Mac 系统只开放本地 Token 连接，官方积分授权明确禁用。当前 Intel Mac 有 TRAE CN 3.4.4 及可读数据库，但 `chat_turn` 为 0 条，故不能以真实 Token 值验收；空库保持未知，不伪报 0。用户在独立官方窗口登录后，安装版读取真实余额并在重启后自动恢复；真实断开清除未操作，避免再次要求用户登录。

## 用户要求与口径

用户要求增加 TRAE 用量及额度监控，并进一步询问能否采用本机日志读取。优先采用真实本机记录，不能直接把官网账号用量混入现有本机总 Token。额度与 Token 保持独立来源；积分不能反推 Token，也不能转换为订阅剩余百分比。

## 已验证：Windows TRAE CN 3.4.4 本地数据库

- 普通运行日志未找到可用的精确 Token 计数。实际来源是应用数据目录下 `Trae CN/ModularData/ai-agent/database.db`，并非 Codex 式明文 JSONL。
- 文件采用 SQLCipher 兼容页格式。参考公开一手实现 [TokenTracker 本地读取说明](https://github.com/xiufengsun/TokenTracker/blob/main/docs/trae.md) 和 [页读取代码](https://github.com/xiufengsun/TokenTracker/blob/main/src/lib/trae-snapshot.js) 后，使用公开的应用级密钥验证本机第一页 HMAC 与页头成功；没有读取、解密或导出账户登录凭据，也没有扫描进程内存。
- 只读试验验证数据库页与 WAL 校验和，只合并已提交 WAL 帧。解密内容仅在内存中供 SQLite 查询；没有创建明文数据库副本，没有修改 TRAE 原文件。读取前后文件大小和修改时间一致。
- `chat_turn.context.token_usage` 存在精确字段：`prompt_tokens`、`completion_tokens`、`total_tokens`、缓存读写与推理计数；`created_at`、`updated_at` 为秒级时间。只查询计数和时间，不输出会话标题、消息、账号标识或凭据。
- 本机样本共 18 条含用量记录；北京时间 2026-10-19 一条，输入 [输入量已脱敏]、输出 [输出量已脱敏]、总计 [总量已脱敏]，缓存读取 [缓存量已脱敏]。与官网当日对应记录的输入/输出一致。缓存与推理字段不能再次简单累加到总量。
- 本次样本的 `prompt_tokens_total`、`completion_tokens_total` 均为 0，不能不加判断地覆盖非零基础字段；多请求 agent 场景的总计字段优先级仍需另行验证。
- 本次数据库约 4.36 MiB，加 WAL 共读取 9,679,968 字节；这只是一次可行性试读，尚未测量运行时增量采集的开销、峰值内存或长期稳定性。

## 已验证：官方账号来源可作独立备选

- 登录后的官方个人用量页使用 `api.trae.cn` 的 `user_current_entitlement_list` 返回积分包额度、已用量及有效期，实际积分余额可与页面核对。精确逐包字段优先于已四舍五入的汇总字段。
- `query_user_usage_group_by_session` 返回输入、输出、缓存计数和实际用量时间。但它是账号口径，不保证仅来自本机；不能因为把 API 结果缓存到本地，就称作本机日志统计。
- 只在已登录的官方网页中核对响应结构；没有把网页登录凭据复制给 TokenDaily。原生 CLI 导出的令牌调用积分端点返回未授权，不能假定不同登录令牌通用。已实现 TokenDaily 独立官方 WebView 登录。原生层只接收白名单余额响应字段，Cookie/令牌留在独立网页配置中；不是复用或解密客户端登录。

## 接入验收与未验证项

1. 今日用量按北京时间 00:00 切日；来源可读且已确认接入时，无当日记录可为 0；权限、校验失败和未知格式仍为未知或带时间的旧值。
2. SQL 只返回必要计数、模型、时间及去重标识；原始上下文和完整明文数据库不落盘、不上传。生产实现需固定内存上限、处理 WAL 并发、写入截断、损坏、删除及版本变化。
3. 不按两秒周期完整读取数据库；通过文件元数据检查、节流和缓存减少重复工作。变更后只查询必要范围，并测量真实更新延迟与开销。
4. 验证会话恢复、云端历史同步和多设备场景的来源归属；数据库位于本机，并不能单凭位置保证每条记录都由本机发起。无法确定时，范围必须注明为“本地记录”，不能承诺严格设备独占。
5. 测试缓存/推理不重复计数，多请求轮次、重复记录、累计字段、修正记录、北京时间切日及溢出拒绝；再合入今日总量和总历史。Token 不推算积分，官网账号用量不与本地记录相加。
6. 悬浮窗最多四个 AI 来源，日历独立；加入第四来源不能被现有四行排序截断。隐藏组件不停止采集、不改变合计范围。
7. 账户余额需独立官方授权与只读核验，未知不补零，不改 TRAE 登录或配置。没有完成之前不宣称额度已接入。
8. Windows 0.1.19 实测见下文；Mac 0.1.22 后续实现和安装态状态见文首，真实 Token 仍待非空来源验证。

原始数据库、私人响应及试读脚本保留在 Git 之外；此文档只记录脱敏结果与来源边界。

## 0.1.19 实现与验收

- 入口：设置中连接 TRAE；今日总览与详情立即读取本地记录，浮窗新增第四 AI 积分卡，支持现有排序/隐藏；总历史只在 TRAE 已连接时加入其本地数据库记录，保持按需扫描。组件隐藏不改变采集或合计。榜单上传仍仅 Codex。
- 实现文件：Rust trae_usage.rs（页认证、已提交 WAL、内存 SQLite、字段投影、去重及按日聚合）、trae.rs（独立连接与后台状态）、trae_credits.rs（独立官网窗口与余额）。路径在 platform 中；前端复用既有 Monitor/CreditState，不改变账号额度契约。
- 读取限制：数据库和 WAL 单文件各 64 MiB 上限，记录最多 200,000 条；超出或校验失败明确未知/旧值，绝不反推或补零。未变化时不读正文、不重新聚合；变化自动重读间隔 30 秒，手动至少 10 秒。跨日只在可确认来源仍正常时为 0。原数据库/日志无写操作，明文仅在内存；临时缓冲清零，不创建明文文件。
- 累计字段：非零 prompt_tokens_total/completion_tokens_total 作为轮次累计值，零值回退基础字段；缓存与推理不重复相加。已用合成用例验证；本机真实样本均为零累计字段，多请求 agent 的完整覆盖仍需后续真实样本核验。没有读取模型计价字段，TRAE 暂不提供 API 费用预估，现有合计明确部分覆盖。
- 官方积分：网页配置位于 TokenDaily 自有数据目录 trae-official-profile，远程页面没有 Tauri IPC 权限；仅观察固定官方端点成功响应中的白名单字段。随机票据、十分钟登录期限、回调来源/有效期校验；不导出 Cookie/令牌，不读取 TRAE 客户端凭据。登录成功后默认五分钟更新，自动失败后六十秒重试，手动至少十秒；网络/页面错误保留旧值并标旧，单次授权异常先复核，连续两次明确异常才清除旧余额并提示重新登录。清除只处理 TokenDaily 独立网页数据，不注销客户端。
- 2026-10-20 补充：仅保存一份规范化的上次成功积分结果，新查询覆盖旧值。Windows 文件受当前用户 DPAPI 保护；Mac 用仅当前用户可读的本机文件保存非凭据余额，授权仍在独立 WebKit 存储。重启时独立网页授权仍启用才显示带查询时间的“上次余额”，后台仍以官方页面响应为实时依据；主动重新登录、明确未授权或清除连接时删除旧值。缓存不含 Cookie、令牌或完整官方响应，也不从本地 Token 推算余额。
