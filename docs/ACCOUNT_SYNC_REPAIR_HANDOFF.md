# Mac 设备连接与汇总验收交接

版本 0.1.27，原任务分支 `codex/account-sync-repair` 已按用户 2026-10-21 的要求快进合入本地 `main`。Windows 已安装验证；Mac 未编译、未安装或实测，功能清单继续标记未完成。由用户自行 push `main` 后，再在 Mac 获取；不覆盖 Mac 尚未提交的改动，也不重置或删除其钥匙串身份、本机日志。

## 已确认的问题

- 官网浏览器登录和桌面设备连接是两件事。云端“测试账户”账号目前只连接一台 Windows。Mac 截图的“试用身份与数据／不支持跨设备登录”界面没有官网连接入口，具体版本无法从截图判断；同昵称的游客不会自动合并进账号。
- Mac 应用显示本周排名，背后网页选择日榜；必须选择相同周期、工具再核对。
- 历史补传曾占满每日预算并挡住当天用量。官网已部署独立 live 预算，桌面此分支优先发送最新用量、今日与历史分批，逐批保留检查点。Windows 真实同步已验证。

## 在 Mac 继续

1. 检查干净工作区，获取用户推送的 `main`，保留本机已有开发工作，并从主线建立短期 Mac 验证分支。阅读 `AGENTS.md`、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT_WORKFLOW.md` 及 `FEATURE_PARITY.md` 的 CHG-20261021-02。
2. 按既有 Mac 环境准备依赖，执行 `npm test`、`npm run build`、`bash scripts/mac-dev.sh cargo test --locked --manifest-path src-tauri/Cargo.toml --features macos-transparent --lib`，以及 Mac 原生编译检查。记录实际结果，不能用 Windows 测试替代。
3. 沿用既有本机测试打包/签名流程，备份当前 App 后安装 0.1.27；保留原 bundle identifier 与钥匙串记录。未启用 Mac 公开更新服务，不通过官网更新按钮获取此版，也不新增付费分发步骤。
4. 应用“我的用量榜”点击“在浏览器连接这台设备”。在浏览器用原来同一邮箱登录，并批准本次设备连接。回应用“连接完成后刷新状态”，再点“立即同步所有已接入工具”。不需要删除或重新建立原游客身份；已有游客历史由服务器分批迁入。
5. 官网账号页刷新后应出现两台已连接设备。比较相同北京时间周期和工具；账号按事件去重，同一事件存在两台电脑时只计一次，因此设备用量之和可能高于账号总量。不要为凑数重复上传、删除账号或清空预算。
6. 确认原设置、来源授权、日志和游客历史保留，重启后连接仍在；验证今日新增继续同步、历史暂停提示与次日恢复。完成后在同一功能清单更新 Mac 结果，再按共仓流程集成。

仅 Codex、Claude Code、WorkBuddy 已接入跨设备汇总；TRAE 仍只有本机数据，不应拿含 TRAE 的本机总量直接比较官网账号总量。官网公开快照最多约 5 分钟延迟，设备默认约 30 分钟同步；即时核对优先看账号页的手动刷新和各设备最近同步时间。
